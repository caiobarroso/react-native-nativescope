---
title: Structured data
description: Inspect objects, arrays and Error values from console calls without flattening them into an unreadable string.
---

## The list is a preview; the detail is the evidence

When a console call receives an object, array or `Error`, Logs serializes a bounded representation
for the wire and keeps the structured argument available in the detail panel. Select the row and
open **Data**, **Argument** or **Error** to inspect it.

The viewer is the same read-only JSON workspace used by Storage. That gives you familiar search,
tree navigation and readable nested values instead of a terminal-style `[Object]` placeholder.

```ts
console.log("[Checkout] created", {
  id: "ord_8Fj2K",
  customer: { name: "Ana Ribeiro", tags: ["vip", "recurring"] },
  totals: { total: 229.9 },
});
```

The stream can show a compact preview such as the order id and total. The detail panel lets you
open the nested customer, tags and totals without logging the object again.

## Errors carry their stack

Passing an `Error` preserves its message and stack when the runtime provides one. Uncaught errors
and unhandled rejections are captured with their source, so they remain distinguishable from an
ordinary `console.error` call.

The stack starts collapsed to keep the useful message visible. Expand it when the frame locations
are the next clue, or use **Copy log** to include it in an issue.

## Bounded values are explicit

Serialization has finite depth, key, array and string limits. If a value is capped, Logs labels it
as capped in the detail panel. A valid bounded JSON representation is more useful than allowing a
cyclic or multi-megabyte object to block the app or the Studio.

See [Configuration](/docs/logs/configuration) to tune the public limits and
[Safety & limits](/docs/logs/safety) for the trade-offs.
